# krea2-studio

Text2image и **edit по референсам** для Krea 2 на чистом `diffusers` + Gradio.

Стоковый `Krea2Pipeline` умеет только `text2image`. Edit-режим — сборка последовательности
с референсными токенами, ось кадра в RoPE, grounded encode и дозирование внимания —
реализован здесь.

**Механика — половина дела.** Базовые веса Krea 2 обучены только под t2i: получив
референс в контексте, они аккуратно его копируют и инструкцию не исполняют (проверено:
`smoke_out/07_lora_off.png` против `07_lora_on.png`). Сам навык редактирования живёт в
community-LoRA [`conradlocke/krea2-identity-edit`](https://huggingface.co/conradlocke/krea2-identity-edit),
обученной ровно под эту раскладку. Она грузится автоматически — см. «Edit-LoRA» ниже.

Механика восстановлена по исходникам `diffusers` и community-ноды для ComfyUI,
а затем проверена на игрушечной модели: сборка последовательности, ось кадра в RoPE,
срез выхода и формулы буста прогонялись ассертами до переноса на реальные веса.

## Как это работает

```
последовательность:  [ текст | реф 1 | реф 2 | цель ]
позиции (t,h,w):     (0,0,0)  (1,h,w) (2,h,w) (0,h,w)
выход:               только целевые токены, срез с конца
```

Референсы — чистые (незашумлённые) VAE-латенты, упакованные так же, как цель, и
помеченные ненулевым номером кадра. Влияют исключительно через self-attention: если
замаскировать их столбцы, результат бит в бит совпадает с чистым t2i.

Второй канал — **grounded encode**: изображение уходит в Qwen3-VL вместе с инструкцией,
как это было в обучении. VAE-токены несут внешность, grounded — семантику сцены.

## Edit-LoRA

| | |
|---|---|
| репозиторий | `conradlocke/krea2-identity-edit` |
| файл по умолчанию | `krea2_identity_edit_v1_2.safetensors` (1.8 ГБ) |
| экономные варианты | `KREA2_EDIT_LORA=r64` (0.46 ГБ) или `r128` (0.91 ГБ) — те же веса, ужатые SVD |
| выключить | `KREA2_EDIT_LORA=off` |

Формат ключей у неё ComfyUI/ai-toolkit (`diffusion_model.blocks.N…`), но diffusers
разворачивает его сам, так что грузится штатным `load_lora_weights` — конвертер не нужен.
Нужен только `peft`.

Адаптер лежит **выключенным** и включается лишь внутри `pipe.edit()`: на чистом t2i он
неуместен. Вручную:

```python
from krea2_studio import Krea2EditPipeline, load_edit_lora
pipe = Krea2EditPipeline.from_pretrained("krea/Krea-2-Turbo", dtype=torch.bfloat16).to("cuda")
load_edit_lora(pipe)                       # или load_edit_lora(pipe, "/path/to/lora.safetensors")
out = pipe.edit(prompt="...", images=[img], processor=processor, fit_mode="fit")
```

`lora_scale=0.0` в `edit()` обнуляет вклад адаптера, не выгружая его, — так устроена
проверка на шаге 8 диагностики.

Рецепт от автора весов: большинство правок — Turbo, 8–12 шагов (10 — баланс между
композицией и лицом), guidance 0.0; удаления объектов — Raw, 20 шагов, guidance 2.0.
`ref_boost ≈ 4` даёт сильное сходство лица, `fit` — геометрия, под которую обучалась v1.2.
Генерировать до 2 Мп: выше начинается дублирование содержимого референса.

## Перенос позы со второго референса

Поза из референса сцены **сама не переносится**. Замерено: тот же кадр, тот же сид,
в инструкции ни слова о позе — фон меняется на нужный, а поза остаётся исходной.
Копирование позы не входит в натренированные навыки LoRA; работает только словесное
описание в инструкции.

Поэтому описание снимается с самого референса — тем же Qwen3-VL, который уже стоит
текстовым энкодером пайплайна. У чекпоинта `tie_word_embeddings=True`, то есть
`lm_head` — это матрица эмбеддингов, уже лежащая в памяти: генератор поверх неё стоит
**ноль дополнительной VRAM** (измерено: +0.00 ГБ) и ~3 секунды.

```python
out = pipe.edit(prompt="create a photo of this woman in her red dress in front of "
                       "a graffiti-covered shutter at night",
                images=[scene, subject], processor=processor,
                fit_mode="fit", auto_pose=True)
print(pipe.last_pose_description)
# The person is crouching low with their torso bent forward, one arm extended
# outward with the palm facing the camera, ...
```

`auto_pose` срабатывает только при двух референсах и описывает `images[0]` — сцену.
При одном референсе он и есть субъект, копировать позу неоткуда.

## Как писать инструкцию

Модель **ненадёжно разрешает ссылки на номера картинок**: «возьми девушку с первого
изображения» приводит к тому, что родной фон субъекта не меняется. Причина видна в
раскладке — vision-блок №1 это сцена, №2 субъект, так что нумерация в такой фразе
оказывается перевёрнутой; но и перевёрнутая работает лишь наполовину (фон смешивается).

Описывайте результат, а не источники:

```
create a photo of this woman in her red dress at night in front of a
graffiti-covered metal roller shutter, harsh flash lighting, gritty urban
street photography
```

Блоки: обращение к субъекту → что обязано выжить → сцена → свет и стиль. Позу
дописывает `auto_pose`.

Если родной фон субъекта всё равно проступает — понижайте `grounding_px` (768 → 512 →
384): ниже значение, сильнее адгезия к правке, слабее сходство лица. Ниже 384 —
за пределами диапазона обучения.

## Замена текстового энкодера

Энкодер у Krea 2 — **немодифицированный** `Qwen/Qwen3-VL-4B-Instruct`. Сверены все
713 тензоров `text_encoder/model.safetensors`: расхождение ноль, отличается только
раскладка ключей (у Krea без префикса `model.`, transformers разбирает обе).

```bash
KREA2_TEXT_ENCODER=<repo_id или путь> python app.py
```

Ограничение жёсткое — **только Qwen3-VL-4B**. Контракт задан трансформером:
`text_hidden_dim=2560`, `num_text_layers=12`, снимаются слои 2..35. У 8B hidden 4096,
`txt_in` и `text_fusion.projector` не сойдутся по форме. `check_compat` проверяет это
до первой генерации.

Перед тем как жечь GPU, померьте, насколько чужие веса уводят вход диффузии:

```python
from krea2_studio import encoder_drift, load_text_encoder
print(encoder_drift(pipe, load_text_encoder("<чужой чекпоинт>")))
```

**Шумовой пол — 0.99995, не 1.0.** Второй экземпляр тех же самых весов уже расходится
с первым на ~5e-5: свои адреса активаций меняют выбор ядер cuBLAS в bf16. Измерено —
второй экземпляр весов Krea и upstream Qwen3-VL-4B-Instruct дают одинаковые `0.99995`.
Сравнивать дрейф файнтюна надо с этим полом.

Чего ждать от замены: `text_fusion` трансформера обучался против hidden states стоковых
весов, так что любой файнтюн — смещение распределения на входе диффузии. Заметный дрейф
означает деградацию, а не новые способности.

## Установка

```bash
pip install -r requirements.txt
```

Репозитории `krea/Krea-2-*` на Hugging Face **gated**: примите условия на странице модели
и положите токен в окружение, иначе загрузка упадёт с 401.

```bash
export HF_TOKEN=hf_...
python app.py
```

Переменные окружения:

| переменная | по умолчанию | зачем |
|---|---|---|
| `KREA2_MODEL` | `krea/Krea-2-Turbo` | `krea/Krea-2-Raw` для базового чекпоинта |
| `KREA2_PROCESSOR` | `Qwen/Qwen3-VL-4B-Instruct` | процессор для grounded encode |
| `KREA2_EDIT_LORA` | `conradlocke/krea2-identity-edit` | `off` — без LoRA, `r64`/`r128` — ужатые варианты, либо путь к своему `.safetensors` |
| `KREA2_OFFLOAD` | `0` | `1` включает CPU-offload при нехватке VRAM |
| `HF_TOKEN` | — | доступ к gated-репозиториям |

## Настройки под чекпоинт

| | Turbo (TDM) | Raw (base) |
|---|---|---|
| шагов | 8 | 28 |
| guidance | **0.0** | 4.5 |

`guidance_scale` у Krea 2 сдвинут: velocity считается как `cond + scale·(cond − uncond)`,
поэтому `4.5` эквивалентно классическому CFG `5.5`, а `0.0` означает «CFG выключен».
Включённый CFG **удваивает** стоимость шага — на Turbo он не нужен.

## Цена edit-режима

Каждый референс добавляет столько же токенов, сколько занимает сама картинка:

| сценарий | длина последовательности | attention ~L² |
|---|---:|---:|
| t2i 496×864 | 2 186 | 1.00× |
| edit 496×864, 1 реф | 3 860 | 3.12× |
| edit 1024×1024, 1 реф | 8 704 | 15.85× |

`ref_boost ≠ 1.0` добавляет плотную матрицу `L×L` (28 МБ на 496×864, 390 МБ на 1328×1328)
и отключает FlashAttention. По умолчанию выключен.

## Структура

```
krea2_studio/
  geometry.py    подгонка референса: crop→resize в пикселях, снап /16, дробное центрирование
  grounding.py   шаблон Qwen3-VL с vision-токенами, динамический prefix_len
  attention.py   ref_boost как additive bias log(b), подмена процессоров внимания
  lora.py        edit-LoRA: разрешение источника, загрузка, включение на время edit()
  describe.py    авто-описание позы со сцены через lm_head, связанный с эмбеддингами
  encoder.py     сменный текстовый энкодер: загрузка, проверка формы, замер дрейфа
  edit.py        Krea2EditPipeline: сборка последовательности, position_ids, денойз-луп
app.py           Gradio: две вкладки
```

## Развёртывание на GPU-инстансе

```bash
export HF_TOKEN=hf_...
bash bootstrap.sh
```

Скрипт ставит зависимости, качает веса в кэш на большом диске и прогоняет диагностику.
Веса тянутся **до** запуска UI — иначе первый запрос в Gradio висит без объяснений.

Отдельно диагностика:

```bash
python smoke_test.py --steps 4
```

Она идёт от простого к сложному — окружение, загрузка модели и LoRA, t2i, edit без
grounding, проверка что референс вообще влияет, grounded encode, буст, геометрия,
вклад LoRA — и на каждом шаге печатает, что делать при провале. Результаты
складываются в `smoke_out/`.

## Статус проверки

Всё проверено исполнением на реальных весах (`krea/Krea-2-Turbo`, RTX A6000 48 ГБ,
torch 2.11 / diffusers 0.41.dev / transformers 5.17): загрузка, t2i, edit с grounding
и без, влияние референса, подмена процессоров внимания под `ref_boost`, обе геометрии,
загрузка edit-LoRA и её вклад в результат. Все 9 шагов диагностики проходят.

Закрытые по ходу проверки вопросы:

* **Vision-токены остаются в условии.** Измерено: 347 токенов (гипотеза «отброшены»
  дала бы ~13). `prefix_len` считается динамически и на дефолтном системном промпте
  совпадает с захардкоженным в diffusers `prompt_template_encode_start_idx = 34`.
* **`ref_boost` подменяет процессоры внимания только у основных блоков.** У `text_fusion`
  внимание идёт по другим осям (12 слоёв энкодера и токены текста), и матрица `L×L`
  оттуда несовместима по форме.
* **Bias строится только ради буста.** Глушить паддинг текста руками не надо: штатный
  forward трансформера собирает key-padding маску из `encoder_attention_mask` сам.
* **С `transformers >= 5` grounded encode требует `mm_token_type_ids`** — без разметки
  модальностей Qwen3-VL отказывается считать M-RoPE. Процессор отдаёт её рядом с
  `input_ids`; на 4.x поля просто нет, и там оно не нужно.
